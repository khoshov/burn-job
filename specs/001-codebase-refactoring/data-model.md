## Domain Model Overview

The refactored architecture relies on strictly typed, immutable domain models partitioned into `burn_job.domain`.

```
┌──────────────────────────────────────────────────────────────────────────┐
│                            PipelineContext                               │
│  - target_dir: Path                                                      │
│  - db_path: Path                                                         │
│  - findings: List[Finding]                                               │
│  - endpoints: List[Endpoint]                                             │
│  - metrics: List[Metric]                                                 │
│  - variants: List[Variant]                                               │
└────────────────────────────────────┬─────────────────────────────────────┘
                                     │
         ┌───────────────────────────┼───────────────────────────┐
         ▼                           ▼                           ▼
  ┌─────────────┐             ┌─────────────┐             ┌─────────────┐
  │   Finding   │             │  Endpoint   │             │   Metric    │
  └──────┬──────┘             └─────────────┘             └─────────────┘
         │
         ▼
  ┌─────────────┐
  │   Variant   │
  └─────────────┘
```

## Core Entities

### 1. `PipelineContext`
Immutable execution state passed sequentially across pipeline stages (scan → ingest → detect → refine → report).

| Field | Type | Description | Validation / Constraints |
|-------|------|-------------|--------------------------|
| `target_path` | `Path` | Directory of target application under analysis | Must exist, must be directory |
| `db_path` | `Path` | Path to KùzuDB database instance | Must be valid file path |
| `endpoints` | `Tuple[Endpoint, ...]` | Discovered target endpoints / controllers | Immutable tuple |
| `findings` | `Tuple[Finding, ...]` | Detected performance defects (T1-T9) | Immutable tuple |
| `metrics` | `Tuple[Metric, ...]` | Static and dynamic metrics gathered | Immutable tuple |
| `variants` | `Tuple[Variant, ...]` | Generated code optimization variants | Immutable tuple |
| `status` | `PipelineStatus` | Current cycle stage enum (`INIT`, `SCANNED`, `INGESTED`, `ANALYZED`, `REFINED`, `COMPLETED`, `FAILED`) | Valid enum state |

---

### 2. `Finding`
Represents a performance defect discovered by static or dynamic detectors.

| Field | Type | Description | Validation / Constraints |
|-------|------|-------------|--------------------------|
| `id` | `str` | Unique finding identifier (UUID / hash) | Non-empty string |
| `rule_id` | `str` | Taxonomy rule identifier (`T1_REDUNDANT_OPS` .. `T9_CPU_HOTSPOTS`) | Valid taxonomy code |
| `title` | `str` | Short human-readable defect title | Max 120 chars |
| `description` | `str` | Detailed explanation of performance defect | Non-empty string |
| `severity` | `Severity` | Severity level (`CRITICAL`, `HIGH`, `MEDIUM`, `LOW`, `INFO`) | Valid enum |
| `location` | `SourceLocation` | File path, line start/end, method name | Valid path & line bounds |
| `metrics_snapshot` | `Dict[str, float]` | Associated metric values (CPU time, allocations, call count) | Key-value mapping |

---

### 3. `Endpoint`
Represents an entrypoint controller or service method analyzed by the pipeline.

| Field | Type | Description | Validation / Constraints |
|-------|------|-------------|--------------------------|
| `name` | `str` | Endpoint method name or route path | Non-empty string |
| `class_name` | `str` | Fully qualified class name | Non-empty string |
| `http_method` | `Optional[str]` | HTTP verb if web endpoint (`GET`, `POST`, etc.) | Uppercase HTTP verb or None |
| `source_location` | `SourceLocation` | Source file and line numbers | Valid location object |

---

### 4. `Metric`
Represents static code metrics or dynamic profiler samples.

| Field | Type | Description | Validation / Constraints |
|-------|------|-------------|--------------------------|
| `name` | `str` | Metric key (e.g., `cpu_time_ms`, `nesting_depth`, `allocations_bytes`) | Non-empty string |
| `value` | `float` | Measured numeric value | Must be >= 0.0 |
| `unit` | `str` | Unit of measurement (`ms`, `bytes`, `count`, `depth`) | Non-empty string |
| `source` | `MetricSource` | Source enum (`STATIC_AST`, `STATIC_JAVAP`, `DYNAMIC_ASYNC_PROFILER`, `DYNAMIC_JFR`) | Valid enum |

---

### 5. `Variant`
Represents a code optimization candidate generated by the refinement agent.

| Field | Type | Description | Validation / Constraints |
|-------|------|-------------|--------------------------|
| `id` | `str` | Unique variant identifier | Non-empty string |
| `finding_id` | `str` | Target finding ID addressed by this variant | Must match valid `Finding.id` |
| `original_code` | `str` | Source code snippet before optimization | Non-empty string |
| `optimized_code` | `str` | Refactored code snippet generated by LLM | Non-empty string |
| `score` | `Optional[float]` | Evaluated optimization score (0.0 to 1.0) | Bounds: 0.0 <= score <= 1.0 |
| `status` | `VariantStatus` | Status enum (`DRAFT`, `COMPILED`, `VERIFIED`, `REJECTED`) | Valid enum |

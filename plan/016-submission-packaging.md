# 016 — Скрипт сборки пакета для сдачи по структуре SUBMISSION.md

## Problem
Корень репозитория уже фактически совпадает с требуемой структурой `<команда>/` из
`TASK/SUBMISSION.md` (`MANIFEST.md`, `skill/`, `RUN.md`, `reports/sandbox/`, `loadtest/`,
`measurements/`, `pr/`, `runlog/` — все на месте, без лишней вложенности). Но в репозитории
также лежат артефакты разработки, которых нет в требуемой структуре и которые не должны попасть
в сдаваемый пакет: `plan/` (спеки этого проекта), `.qwen/`/`.claude/` (конфиги агентских
инструментов), `TASK/` (сама постановка задачи, не продукт команды), `examples/` (136K
демонстрационных Java-файлов T1-T9 + non_defects + `*_FixedByAgent.java`, использовавшихся для
проверки пайплайна детекта), устаревший `scripts/README.md` (описывает скрипты-анализаторы по
пути, где их больше нет — они переехали в `skill/scripts/`), и дублирующийся
`skill/runlog/agent_run.log` рядом с основным `runlog/agent_run.log`. Никакого скрипта, который
собирал бы чистую копию под сдачу, сейчас нет.

## Goal
Добавить скрипт `scripts/package_submission.sh`, который неразрушающе (без удаления чего-либо из
рабочего репозитория) собирает копию/архив, содержащую только то, что разрешено структурой
`TASK/SUBMISSION.md`, исключая артефакты разработки.

## Non-goals
- Не удалять `plan/`, `examples/`, `TASK/`, `.qwen/`, `.claude/` из рабочего репозитория — они
  остаются как есть для разработки; исключаются только из **пакета**.
- Не чинить содержательную неполноту `pr/optimizations.patch` (сейчас там только тоггл
  `spring.jpa.open-in-view`, а не реальные правки N+1/batching/projection) — отдельная задача,
  не в этой спеке.
- Не заполнять `reports/control/` — актуально только если команде выдан control-проект.
- Не менять содержимое `MANIFEST.md`/`RUN.md`/`reports/sandbox/*` — только проверять их наличие
  при сборке пакета.

## Approach
1. Новый скрипт `scripts/package_submission.sh` (bash), аргумент — путь назначения (по умолчанию
   `dist/submission/` + архив `dist/submission.tar.gz`):
   - Копирует: `MANIFEST.md`, `RUN.md`, `pom.xml`, `src/main/**` и конфигурацию (`src/main/resources/**`),
     `skill/` (без `skill/scripts/__pycache__`, `skill/scripts/analyzers/__pycache__`,
     `skill/tools/*.class`, и без `skill/runlog/` — см. пункт про runlog ниже),
     `reports/` (`sandbox/` целиком + `control/`, если существует), `loadtest/`, `measurements/`,
     `pr/`, `runlog/` (только корневой).
   - Явно исключает: `plan/`, `.qwen/`, `.claude/`, `TASK/`, `examples/`, `.git/`, `__pycache__/`,
     `*.pyc`, `*.class`, `*.db`, `*.collapsed`, `src/test/**` (судья восстанавливает свою версию
     тестов по `TASK/SUBMISSION.md`, включать свою — источник путаницы, не пользы).
   - После копирования запускает проверку: каждый обязательный элемент верхнего уровня
     (`MANIFEST.md`, `skill/`, `RUN.md`, `reports/sandbox/report.md`,
     `reports/sandbox/findings.json`, `loadtest/`, `measurements/`, `pr/`, `runlog/`) должен
     присутствовать в собранной копии — иначе скрипт завершается с ошибкой и точным указанием,
     чего не хватает.
   - Упаковывает результат в `dist/submission.tar.gz`, оставляя и несжатую директорию для
     ручной проверки перед сдачей.
2. Исправить `scripts/README.md` — заменить устаревшее описание (ссылается на анализаторы по
   несуществующему здесь пути) на короткое: где на самом деле лежит пайплайн (`skill/scripts/`)
   и что делает `package_submission.sh`.
3. Зафиксировать `runlog/agent_run.log` (корневой) как единственный авторитетный лог для пакета;
   `skill/runlog/agent_run.log` остаётся в рабочем репозитории (если `llm_agent.py` всё ещё
   пишет туда — не трогаем логику записи в этой спеке), но не копируется в пакет, чтобы не
   было двух версий одного лога в сдаваемой структуре.
4. Добавить `dist/` в `.gitignore` — собранный пакет не должен попадать в историю репозитория
   разработки.

## Files touched
- New: `scripts/package_submission.sh`
- Modified: `scripts/README.md` (заменить устаревшее содержимое)
- Modified: `.gitignore` (добавить `dist/`)

## Acceptance criteria
- [ ] Запуск `scripts/package_submission.sh` производит директорию/архив, содержащую ровно
      структуру `TASK/SUBMISSION.md` (плюс `src/main/**`/`pom.xml`/конфигурацию, как того требует
      раздел "Как это будет судиться") — ничего лишнего
- [ ] `plan/`, `.qwen/`, `.claude/`, `TASK/`, `examples/`, `__pycache__`, `*.class`, `*.db`,
      `*.collapsed`, `src/test/**` отсутствуют в собранном пакете
- [ ] В пакете ровно один `runlog/agent_run.log` (корневой), не два
- [ ] Рабочий репозиторий разработки не теряет и не перемещает ни одного файла — только новый
      скрипт, правка `scripts/README.md` и добавление `dist/` в `.gitignore`
- [ ] `scripts/README.md` больше не ссылается на несуществующие пути
- [ ] Скрипт завершается с понятной ошибкой, если на момент сборки отсутствует обязательный
      элемент верхнего уровня

## Dependencies
Не зависит от 001–015 (ортогональная задача упаковки/гигиены репозитория). Стоит перезапускать
всякий раз, когда меняются `reports/sandbox/findings.json` ([004](004-findings-json-generator.md),
[015](015-findings-evidence-schema-compliance.md)) или содержимое `MANIFEST.md`/`pr/`, так как
это шаг снятия снимка перед сдачей, а не постоянно поддерживаемое состояние.

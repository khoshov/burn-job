# 012 — Раздел 7: проверка реальных доказательств вместо текста описания

## Problem

`classify_anomaly_as_non_defect()` (`skill/scripts/non_defects.py:60-102`) — самореферентная
проверка: она матчит подстроки в поле `description`, которое сам же анализатор T1-T9 сгенерировал
шаблонной f-строкой несколькими строками выше по стеку вызова. Ни одно из полей
`evidence_required`, заявленных в `NON_DEFECT_RULES` (`non_defects.py:20-57`) — "JOL layout
measurement", "API contract validation ensuring N≤8", "Configured eviction policy" — фактически
не проверяется, это чисто документационные строки.

Дополнительно найдено: правило ND-5 (`non_defects.py:95-96`, ветка `pct > 0 and pct < 0.5`) —
безусловный "пылесос", отменяющий любую аномалию любой категории с маленьким процентом, из-за
чего в нашем тесте одни и те же по сути ложные срабатывания (JIT-фреймы) разделились на
`DEFECT`/`NON_DEFECT` только по величине `pct`, а не по причине.

## Goal

Каждое правило Раздела 7 проверяет реальные данные, теперь доступные после
[005](005-allocation-based-t4-t8.md)/[006](006-leak-detection-t7.md)/[008](008-static-callgraph-reachability-t5.md),
вместо повторного парсинга сгенерированного текста.

## Non-goals

- Не менять сам список правил ND-1..ND-6 или их формулировки — только механизм проверки.
- Не убирать текстовый фолбэк полностью — там, где реальных данных ещё нет (например проект
  не подключил статический анализ), старая текстовая эвристика остаётся как деградация,
  но явно помечается более низкой уверенностью (`confidence: "heuristic"` vs `"verified"`).

## Approach

Переписать `classify_anomaly_as_non_defect()` так, чтобы каждое правило принимало не только
`anomaly` (словарь с текстом), но и опциональный контекст с реальными данными:

- **ND-1 (field ordering)** — вызывает `object_layout.compute_static_object_layout()` из
  [005](005-allocation-based-t4-t8.md) и сравнивает фактический размер объекта до/после
  реордеринга полей; засчитывается non-defect только если разница действительно 0, а не по
  наличию слова "jol" в тексте.
- **ND-2 (bounded quadratic)** — вызывает [008](008-static-callgraph-reachability-t5.md)/[009](009-static-pattern-detection-t1-t2-t3-t6.md)
  для проверки, действительно ли размер входной коллекции ограничен `@Max`/`Math.min` в
  сигнатуре метода (статическая проверка контракта), а не текстовый поиск `"n<=8"`.
- **ND-3 (bounded cache)** — использует новый `UNBOUNDED_GROWTH_TREND` из
  [006](006-leak-detection-t7.md): non-defect засчитывается, если retained-count не растёт
  между `runId`, а не по наличию слова "caffeine" в имени класса.
- **ND-4 (bounded request collection)** — статическая проверка наличия `@Max`/валидации
  параметра пагинации в сигнатуре контроллера (переиспользует инфраструктуру
  [009](009-static-pattern-detection-t1-t2-t3-t6.md)).
- **ND-5 (microbenchmark noise)** — убрать безусловную ветку `pct > 0 and pct < 0.5` для всех
  категорий; оставить только целевую проверку для `Pattern.compile`-подобных аномалий с явным
  порогом (согласуется с фиксом в [007](007-lock-contention-t9-and-regex-fix.md), где сам
  Cypher-запрос уже получает свой порог — здесь дополнительно убирается дублирующий,
  неконтролируемый общий фильтр).
- **ND-6 (code style)** — остаётся текстовой эвристикой (реальной проверки "код стиля не влияет
  на байткод" без полноценного diff байткода до/после не сделать в рамках этого плана) —
  явно помечается `confidence: "heuristic"`.

## Acceptance criteria

- [ ] ND-1 не засчитывает non-defect на классе, где статический расчёт layout показывает
      реальную экономию от реордеринга полей (было бы false negative на реальном дефекте).
- [ ] ND-3 требует данные тренда из [006](006-leak-detection-t7.md); без них (только один
      `runId` в базе) правило явно возвращает `confidence: "heuristic"`, а не молчаливо считает
      подтверждённым.
- [ ] Regression на нашем тестовом прогоне этой сессии: 8 срабатываний
      `MICROBENCHMARK_REGEX_COMPILE` на JIT-фреймах теперь либо не появляются вовсе (после
      [007](007-lock-contention-t9-and-regex-fix.md)), либо, если появились как аномалия другого
      рода, не получают ND-5 только из-за низкого `pct` без содержательной причины.
- [ ] Каждая non-defect классификация в выводе содержит поле `confidence` (`verified`/`heuristic`),
      различающее случаи, где проверялись реальные данные, от случаев текстового фолбэка.
